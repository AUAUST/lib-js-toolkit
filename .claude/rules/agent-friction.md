# Agent friction

- Append one line to `.ai/friction.md` each time your tools or workflow, rather than your work, cost you a retry, a workaround or a lookup.
- Count as friction a command that behaved otherwise than you expected, a permission or tool that blocked you, and any fact about your tools or workflow you had to search for because no instruction or command gave it to you.
- Log within the task in which it happens, without asking first.
- Write each line as `- <subject>: <what you tried> — <what stopped it and how you got past>`, a few words each, naming the command, tool or instruction as the subject so repeated mentions match.
- Create the file when absent, under a `# Agent friction` heading.
- When the log already holds lines on the subject, report it as a fix candidate with the number of its lines.
- Remove a subject's lines when a backlog entry, an issue or a change takes up its fix.
- Keep failures your work causes out of the log, and record defects of the project in the backlog.
